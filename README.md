# JTR: Journal of Total Rejection

A static site. No build step, no framework, no dependencies.

## Files

| Path | Purpose |
|---|---|
| `index.html` | Home: status bar, intro, latest three decisions |
| `archive.html` | Every decision, filterable by field |
| `certificate.html?id=JTR-…` | One printable certificate per manuscript |
| `submit.html` | Submission form |
| `404.html` | Shown for unknown URLs |
| `rejections.json` | The data. Add entries here. |
| `assets/style.css` | All styles |
| `assets/site.js` | All behaviour. Holds the form endpoint. |
| `robots.txt`, `sitemap.xml` | Search engine files |

## Before you publish

1. **Set your domain.** Replace `https://example.com` in `sitemap.xml` and `robots.txt`.
2. **Connect the form.** Create a form at formspree.io, copy its ID, and replace `YOUR_FORM_ID` in `assets/site.js`. Formspree emails each submission to you.
3. **Replace the sample entries** in `rejections.json` with your own.
4. **Add certificate URLs to `sitemap.xml`** if you want them indexed. One `<url>` line per manuscript.

## Preview locally

The site loads `rejections.json` with `fetch`, which browsers block on `file://`. Serve the folder instead:

```
cd jtr-site
python3 -m http.server 8000
```

Then open http://localhost:8000.

## Adding a decision

Append an object to `rejections.json`:

```json
{
  "id": "JTR-2026-0042",
  "field": "Applied Epistemology",
  "date": "2026-10-01",
  "title": "Paper title",
  "author": "Author or pseudonym",
  "verdict": "The editor's rejection note."
}
```

Keep `id` unique. Dates use `YYYY-MM-DD`. The site sorts entries by date automatically.

## Publish

Any static host works. Pick one:

- **Netlify:** drag the `jtr-site` folder onto app.netlify.com/drop. You get a live URL immediately. Add a custom domain in site settings.
- **Vercel:** install the Vercel CLI and run `vercel` inside the folder, or import the folder from a Git repository.
- **GitHub Pages:** push the folder to a repository, then enable Pages under Settings, choosing the main branch and the root folder.

All three serve `404.html` for missing pages automatically.

## Pre-launch checklist

- [ ] Domain set in `sitemap.xml` and `robots.txt`
- [ ] Formspree endpoint set, and a test submission received
- [ ] Sample entries replaced
- [ ] Checked on a phone-width screen
- [ ] Printed one certificate (Print button on any certificate page)

## Search engine setup

- Every page has a unique title, meta description, canonical URL, and Open Graph and Twitter card tags.
- The home page has WebSite structured data.
- After your domain is live, submit `sitemap.xml` in Google Search Console and Bing Webmaster Tools.
- Before launch, replace `https://example.com` everywhere (`sitemap.xml`, `robots.txt`, and the `seo` blocks in each HTML file). A quick find-and-replace in your editor handles it.
- Add each certificate URL to `sitemap.xml` when you publish a new decision, or let the sitemap be regenerated by your host.
